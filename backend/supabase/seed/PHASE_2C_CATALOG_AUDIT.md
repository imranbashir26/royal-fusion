This is a source audit, not a claim about the contents of a live Supabase project. No live database was read or changed. `001_starter_catalog.sql` explicitly calls its rows fictional and uses `replace-cloud-name` media; `db.json` is a prototype; `frontend/src/data/products.ts` is a bundled local fallback. These seven slugs appear in all three sources. No genuine Attar or Gift Set product is evidenced.

All three sources price the seven products at PKR 3,990 with old price PKR 4,590; S has null sale price, P has `salePrice: 0`, and B has no sale price. All seven S rows are `Published` and active; P rows are `Published` but have no explicit `active`; B has no status field.

`EDP` means Eau de Parfum, supported by the explicit `concentration` field in S and P. The P SKU corresponds to a 50ml variant in S, not to S's base product SKU. S prices and stock are fictional fixture values, not verified commercial inventory. The SQL normalization script therefore requires the exact S base SKU and does not overwrite pricing, stock, flags, gender, scent, copy, or media. The conflicting flag, gender, stock, and SKU values require a production operator to verify against approved business records before any live catalog population.

Canonical categories are `Eau de Parfum`, `Extrait de Parfum`, `Attar`, and `Gift Set`. S has legacy For Him, For Her, Unisex, Attars, Gift Sets, and Best Sellers category records; P has ten navigation/facet labels as categories. The SQL normalization script retires unreferenced legacy facet categories and renames the plural type records while preserving their IDs. It aborts on conflicting singular/plural records or unknown references. No Attar/Gift Set rows are created.

The prototype JSON remains an untouched local fixture containing orders and other unrelated records. The development storefront normalizes its product type from the explicit concentration at read time and uses the canonical bundled type list, without changing prototype prices, stock, flags, or media. Production never falls back to those prototype products or categories.

Collection slugs are `royal-fusion-originals`, `crystal-edit`, and `oud-heritage`; `royal-collection` remains a frontend alias. S has explicit `product_collections` rows for six Originals products and CRIMSON CRYSTAL in Crystal Edit. B has only three Originals links and one Crystal Edit link. P has no collections array or relational links, only legacy `products.collection` text. The SQL script can restore only the explicitly documented S links when the exact S product identities are present; it leaves all other membership unresolved. Oud Heritage has no evidenced product assignment.

Media gaps: S Cloudinary URLs use `replace-cloud-name` and are placeholders; P/B `/uploads/products/*.webp` files are absent from this workspace. Gallery entries repeat those paths. P/B card image and hover fields are generally absent; B's CRIMSON CRYSTAL card image exists, but its hover path is absent. Card background colors exist in B only. No media is uploaded or replaced in Phase 2C.

Inventory and pricing review: all source stock numbers are nonnegative, and PKR 3,990 / 4,590 meets the current Product API constraints. S has 75 units per base product and three 25-unit variants; P/B disagree on base stock. No stock or price is changed. Published/active consistency of live records, actual media availability, and genuine commercial values remain unverified without operator access to production data.
